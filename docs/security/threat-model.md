# Agentropy threat model — identity flows (M2-09, FEAT-027.7)

**Status:** revision 3 (2026-11-06; TM-29…TM-31 added by FEAT-028.4, TM-32…TM-33 by FEAT-028.5, TM-34 by FEAT-028.9, TM-35…TM-36 by FEAT-029.2, TM-37…TM-41 and flow F9 by TASK-034.3, TM-42 by FEAT-034.1, TM-43 by FEAT-038.4, TM-44 by TASK-035.1, TM-45 by FEAT-040.2, TM-46 by FEAT-035.1). STRIDE analysis of every identity-bearing flow in the runtime, its ingress adapters, and deployments where several workers share one store (F9). Each mitigation names the test that proves it; `node scripts/check-readiness.mjs` fails if a referenced test file is missing. Rows marked *planned* name the backlog root that owns them. Related: [Security v1](../contracts/security-v1.md), [ADR-0021](../adr/0021-delegated-authorization.md), [ADR-0024](../adr/0024-pre-dispatch-authorization-gate.md).

## Trust boundaries and assets

- **Boundaries:** (B1) transport → runtime (HTTP, queue, webhook adapters hand over an authenticated principal); (B2) agent → agent inside the runtime; (B3) runtime → providers (tools, model APIs, workflow engines, credential store, policy point); (B4) runtime → store, which in multi-worker deployments is also the only channel between workers (SQLite file or PostgreSQL server); (B5) runtime → telemetry/audit sinks; (B6) runtime ↔ remote A2A peers (planned).
- **Assets:** task inputs/outputs and checkpoints, delegated grants, credentials, inbox content, human decisions, audit trail, tenant separation.
- **Assumptions:** the transport authenticates callers and maps them to a `TrustedPrincipal`; the store and process are not attacker-controlled (store tampering is detected for audit rows only); policy and grant services are trusted but may be unavailable.

## Token and authority lifetimes

| Artifact | Lifetime | Freshness rule |
|---|---|---|
| Delegated grant (`delegatedAuthorityRef`) | Issuer-defined | Checked at acceptance, at every dispatch (gate) and before every protected effect; never cached |
| Narrowed child grant | No longer than its parent | Derived per child task by `GrantVerifier.narrow` |
| Policy decision | ≤ `ttlMs` (default 30 s) when `CachingPolicyDecisionPoint` is used; with `shared`, a revocation reaches other workers within `syncMs` (default 1 s) | Invalidated by `revokeAuthority` (on every worker sharing the store when `shared` is set), by a new policy version, or by expiry; failures never cached; a failed invalidation read clears the cache |
| Credential (API keys, tokens) | Provider-defined | Resolved per invocation, never stored or cached by the runtime |
| Human-action claim | 15 min default | Lapses back to `pending`; decisions re-check assignment, authority and revision |
| Trace context | Per request | Correlation only; validated and never an authorization input |

## Residual risks (accepted for M2)

- A compromised process or store can read task data; encryption at rest and KMS integration are deployment concerns (FEAT-028.5/.8). Audit anchoring protects only as well as the anchor sink is isolated from store writers.
- Break-glass is not adopted; administrative dual control and data residency are deployment policy ([ADR-0030](../adr/0030-hardening-and-d24-decisions.md)).
- Quotas are per tenant only; per-user quotas and cost attribution are M3.
- **Multi-worker deployments (F9).** Every worker holds the same store credentials, and anything that can write the store is trusted as a worker: it can claim work under any `workerId` and read every tenant's data. Mitigations are deployment policy: one database role per deployment with rights on its own schema only, TLS to the database, and the default-deny NetworkPolicy (`deploy/kubernetes`) so only worker pods reach the database. Per-worker identities and row-level tenant isolation in the database are not implemented.
- Between a revocation and the next sync, a worker with a shared decision cache may still allow the revoked grant for up to `syncMs`; a worker whose cache is not `shared` keeps cached allows for up to `ttlMs`. Grants themselves are re-checked before every protected effect, so this window covers policy decisions only.
